01 / Getting set up

Developer setup

For collaborators with repository access. The source repository is private. A public installer download has not been published. Check current availability →

You need Python 3.11+ and Git. Running Java tests also needs JDK 17+ with Maven or Gradle.

TERMINAL / SOURCE SETUP
git clone https://github.com/mohibk0004-del/codedna
cd codedna
pip install -e ".[api,ml]"
pip install -e plugins/codedna-java -e plugins/codedna-python
codedna --version

The desktop IDE is built from ide/ using Node 22. Run npm install, then npm run build and npm start. A Windows installer is produced with npm run package --workspace electron-app.

Language plugins

Open Extensions → Language plugins in the IDE, or press Ctrl+Shift+X. Java and Python are bundled. Optional published versions use the same official catalogue as this website. Analysis plugins are separate from editor completion and debugging extensions.

02 / Start with a comparison

Your first analysis

Point CodeDNA at a local Git repository and choose the revisions to compare. You can also inspect changes you have not committed yet.

TERMINAL / CHANGE → IMPACT → TESTS
# What changed in the last commit, and what it may affect
codedna impact --repo . --base HEAD~1 --head HEAD

# The same for edits you have not committed yet
codedna impact --repo . --base HEAD --head WORKTREE

# Tests to run, with reasons
codedna select --repo . --base HEAD~1 --head HEAD --strategy dependency
03 / Read the relationships

Understand the impact graph

CodeDNA maps changed declarations and follows reverse dependencies into potentially affected code and tests. The graph distinguishes confirmed relationships from heuristic ones. References it cannot resolve stay explicitly unresolved.

A dependency path explains why code may be affected. It is not proof that a test will fail, and the graph does not claim to capture every runtime relationship.

04 / Execution is explicit

Running tests

Running tests executes the project's own code. CodeDNA only does this when you explicitly pass --allow-build.

TERMINAL / AUTHORIZED TEST EXECUTION
codedna run-tests --repo . --output-dir out --allow-build

Maven projects run from the root reactor. Gradle projects use the Gradle on your PATH; the repository's gradlew is never run. Your project still needs its build dependencies.

05 / Language support

Python and mixed projects

Python uses static pytest discovery and the project interpreter. Put pytest and your dependencies in the project's .venv, or choose an interpreter with --python.

Python and mixed projects conservatively use the full-suite risk fallback. Java risk-model evidence does not transfer automatically. No cross-language dependency edges are inferred.

06 / Evidence before estimates

Risk and fallback

codedna risk-select fits a model on the project's own older history, audits it on later history, and only uses risk-based skipping when the evidence gates pass. Stale or insufficient history, a failed audit, or unsupported changes lead to a broader or full-suite recommendation with reasons.

TERMINAL / JAVA RISK SELECTION
codedna risk-select --repo . --base HEAD~1 --head HEAD
# Reads .codedna/history.csv unless you pass --history-csv FILE

History preparation is described in docs/JAVA_WORKFLOW.md in the repository. Risk estimates are evidence, not guarantees that skipped tests will pass.

07 / A check before done

Agent workflows

The existing agent brake and MCP interface let a coding agent request a test plan and check recorded execution results. Required tests that are missing or skipped cannot count as a complete passing check.

Execution permission is configured explicitly for the repository. An agent cannot grant itself build permission. Consult codedna mcp --help and the repository documentation for the supported options.
