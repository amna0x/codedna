Install

You need Python 3.11+, Git, and for running tests a JDK 17+ with Maven or Gradle.

git clone https://github.com/mohibk0004-del/codedna
cd codedna
pip install -e ".[api,ml]"
pip install -e plugins/codedna-java -e plugins/codedna-python
codedna --version

The desktop IDE is built from ide/ (Node 22): npm install, then npm run build and npm start. A Windows installer is produced with npm run package --workspace electron-app.

Language plugins

Open Extensions → Language plugins in the IDE, or press Ctrl+Shift+X. Java and Python are bundled. Optional published versions use the same official catalogue as this website. CodeDNA analysis plugins are separate from editor completion/debugging extensions.

First run

# what changed in the last commit, and what it may affect
codedna impact --repo . --base HEAD~1 --head HEAD

# the same for edits you have not committed yet
codedna impact --repo . --base HEAD --head WORKTREE

# tests to run, with reasons
codedna select --repo . --base HEAD~1 --head HEAD --strategy dependency

Running tests

Running tests executes the project's own code, so CodeDNA only does it when you pass --allow-build:

codedna run-tests --repo . --output-dir out --allow-build

Maven projects run from the root reactor; Gradle projects use the Gradle on your PATH (the repository's gradlew is never run).

Python and mixed projects

Python uses static pytest discovery and the project interpreter. Put pytest and your dependencies in the project's .venv, or select an interpreter with --python. Mixed execution is supported, but risk selection conservatively requires the full suite. No cross-language dependency edges are inferred.

Risk-based selection

codedna risk-select fits a model on the project's own older history, audits it on later history, and only then estimates the chance that a skipped test fails. If the audit fails or the history is stale, it recommends the full suite and says why.

codedna risk-select --repo . --base HEAD~1 --head HEAD
# history is read from .codedna/history.csv unless you pass --history-csv FILE

How to prepare that history is described in docs/JAVA_WORKFLOW.md in the repository.
