# CodeDNA product context

## Register

product

## Users

Students and developers reviewing a local project's changes, including people
new to regression testing. The IDE must support a short, teachable demo.

## Product Purpose

Show what changed, what might be affected, and which existing tests to run.
Explain the selection and show actual outcomes after an explicitly approved run.
The Python core owns analysis; the IDE displays its JSON results.

## Brand Personality

Calm, clear, honest. Existing direction comes from DECISIONS.md D-031 and the
newcomer-friendly Changes and Tests to run views, rather than a new brand brief.

## Anti-references

Avoid glowing AI dashboards, jargon-first controls, decorative effects, and
claims that a dependency link or estimated skip risk guarantees safety.

## Design Principles

- Make the next action obvious: compare, recommend, review, then run.
- Use plain language before technical evidence; keep details available.
- Preserve conservative fallback and explicit build consent.
- Distinguish source-discovered checks, actual test outcomes, and audited risk.
- Keep saved research findings separate from the live project demo.

## Accessibility & Inclusion

Preserve native labels, keyboard controls, visible focus, semantic details and
status announcements. Existing D-031 direction supports reduced motion,
contrast and meaningful state labels. No new accessibility certification claimed.
