# Brake improvement plan - honest research follow-up

The owner wants stronger results. This is a development plan, not a claim of
success or a completed preregistered study. Original studies remain immutable.
Correctness repairs and clearer evidence do not establish a speed/safety win.

## Already improved

Required skipped tests no longer pass the brake or replace complete history.
Python/mixed projects use full-suite fallback and real execution. The same
immutable snapshot supplies structural and statistical plans. The agent now
receives the exact omitted-failure objective and active audit denominator,
sample size, bound type and explicit absence of a future guarantee.

## Next research work, kept separate from the website release

1. Implement a deployment-faithful replay with separate policy observation
   stores. Full labels are evaluator-only. Recompute history features and
   training/calibration data using only released observations.
2. Add leak tests: changing an unobserved outcome must not change decisions
   before it becomes visible through execution/audit. Skipped never means passed.
3. On two development projects, evaluate structure alone, statistical stopping
   alone, their union and full-suite fallback. Include a difficult inspected
   case such as Cloudify; do not optimize by simply excluding it.
4. Include random full audits and their costs. Specify completion timing from
   real timestamps if available, otherwise disclose a sequential assumption.
5. Measure omitted-failure safety among failing commits, build escapes and
   failing-test recall separately. Also report first failures, audit/fallback
   frequency, total test cost and selector overhead. Use attainable matched
   costs and safety-cost frontiers; do not call a failed match a fair win.
6. Freeze methods, comparisons, uncertainty, audit schedule and success criteria
   after development but before accessing a new held-out period/project. Commit
   the protocol and input identities. The already inspected nine projects do
   not become fresh confirmation again merely by renaming output folders.
7. Compare against strong history/DANTE-style rules and appropriate prior
   audited/censored-feedback methods. Label adaptations as adaptations.
8. Promote a candidate only if fresh evidence supports its safety and useful
   savings after overhead. Otherwise retain the conservative default and report
   the negative result. Never weaken a gate merely to obtain more skips.

A useful contribution could be the measured value/cost of the structural floor
under incomplete feedback and the stricter any-omitted-failure objective. It is
not enough to add an audit, conformal calibration or an MCP tool; those have
prior art. No method can promise both arbitrary time savings and no missed
failures on arbitrary future projects.
